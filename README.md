# 秋和PC 硬件测试工具

Windows 硬件检测、快速压力测试与诊断验收工具。

核心流程：启动 → 自动识别硬件 → 待机采样 → CPU 和显卡同时满载（双烤）→ 自动统计 → 生成测试报告 → 在网站的服务表单导入 JSON。

本项目自成一体，不依赖网站仓库的代码、配置或脚本。

**状态：功能开发完成，尚未完成正式发布所需的真实硬件验证。** 已验证和未验证的内容见 [验证记录](docs/validation-record.md)。

## 结构

| 路径 | 内容 |
| --- | --- |
| `src/AkikazuHardwareCheck.Core` | 硬件识别、传感器、采样统计、压力测试、判定、报告、四种语言 |
| `src/AkikazuHardwareCheck.App` | WinForms 界面 |
| `src/AkikazuHardwareCheck.Probe` | 控制台探针，用于现场诊断和实机验证 |
| `tests/AkikazuHardwareCheck.Core.Tests` | 单元测试 |

| `scripts/publish-store-msix.ps1` | 使用 Partner Center 身份生成 Store MSIX |
| `licenses/` | 第三方许可证全文 |
| `third-party/pawnio/` | 未修改的官方 PawnIO 安装程序，嵌入程序 |

## 构建与测试

需要 .NET SDK 10（见 `global.json`）。想直接看窗口：双击 `scripts/run.cmd`，或在 VS Code 按 F5（调试）、运行任务里的“运行工具”。命令行在本目录运行：

```bash
dotnet build AkikazuHardwareCheck.slnx -c Release
```

```bash
./tests/AkikazuHardwareCheck.Core.Tests/bin/Release/net10.0-windows/win-x64/AkikazuHardwareCheck.Core.Tests.exe
```

测试项目使用 xunit.v3 自托管运行，不依赖 `dotnet test`。

生成发布包（单个 EXE，无需安装 .NET，附许可证和 SHA-256，并打包为固定文件名的 `AkikazuHardwareCheck-win-x64.zip`，用于 GitHub Release）：

```bash
powershell -ExecutionPolicy Bypass -File scripts/publish.ps1
```

项目维护三种 Windows 发行物：Portable ZIP/EXE 和 MSI 使用完整 `Website` 能力；Microsoft Store MSIX 使用
受限 `Store` 能力，不含 PawnIO、不自动提权，也不提供修改系统或其他进程的入口。MSI 和 MSIX 的身份、签名、
安装验证及必须由发行者提供的参数见 [发布清单](docs/release-checklist.md)。

## 权限和驱动

- 下载后双击运行，Windows 询问时点“是”，其余全部自动。这一下由 Windows 决定，任何程序都不能跳过。
- 工具内置官方签名的 PawnIO 2.2.0 安装程序，缺少时先校验 SHA-256，再静默安装。CPU 温度、主板风扇和 PUMP 都依赖它。
- 由本次运行安装的驱动，退出时自动卸载。官方卸载程序会留下驱动服务和驱动包，工具会一并删除并核对。主程序退出前一直占用驱动，所以这一步由它启动的子进程在它退出后完成。只有运行前系统里没有这个驱动时才删，原本就有的不动。
- 点“否”时工具继续以普通权限运行，读不到的项目显示为无法取得，也可之后点“以管理员重启”。
- 控制台探针不安装驱动。
- 读不到的项目和没有的设备都不显示，只显示真实读到的内容。读不到不当作硬件故障。
- 发布版运行时需要可写的 `%TEMP%`（WinForms 和原生库释放要用）。

## 读取内容

界面可在“完整信息”和“主要硬件”之间切换，选择会被记住。

| 视图 | 内容 |
| --- | --- |
| 主要硬件 | 笔记本电脑或台式电脑（品牌机）、处理器、显卡、主板、内存、硬盘、显示器 |
| 完整信息 | 另加实时时间和时区（最上方）、CPU 微码、BIOS 版本和日期、有线和无线网卡、显卡驱动（发行方、版本、日期）、硬盘健康、电池、系统盘空间、当前网络、系统和激活状态、语言环境、安全启动和 TPM、散热、键鼠、扬声器、麦克风、摄像头，最下方是系统记录。没有的设备不显示 |

判断规则：

- **网络**：Wi-Fi、网线或无网络。只看有网关的实体网卡，不发送任何数据。
- **扬声器**：接上的扬声器、耳机、USB 和蓝牙设备，以及显示器音频。显示器是否自带喇叭无法可靠判断（EDID 在没有喇叭的显示器上也可能声明支持音频），所以按扬声器显示，是否真的有声由“外设测试”确认。S/PDIF 不算。
- **麦克风**：只算麦克风和耳麦，虚拟设备和立体声混音不算。
- **键鼠**：游戏鼠标和键盘互相注册对方的接口，无法可靠区分，所以合称“键鼠”。
- **触控板、触摸屏、手柄**：用 HID 用途码识别，有才显示。
- **散热器品牌**：USB 水冷能报告产品名时显示，其他情况不显示。
- **TPM、安全启动**：不需要管理员权限。传统 BIOS 模式没有安全启动，显示为无法取得。
- **Wi-Fi 信号**：用系统 Native Wifi API 读百分比，不读取网络名称。普通权限下实测读不到（管理员权限下读到），读不到时不显示。
- **语言环境**：显示语言、区域格式、系统区域和系统编码合并显示，三者相同时只显示一个语言名称。
- **系统记录**：合并显示 Windows 安装日期和上次开机时间；大版本升级后安装日期可能变成升级当天。
- **CPU 信息窗口**：测试控制区的按钮，显示插槽、核心和线程、标称最高频率、缓存、型号标识、虚拟化、微码和 WHEA 错误。WHEA 是系统日志里近 30 天的 WHEA-Logger 事件数（含已纠正错误），大于 0 时标红。测试结束后重新读取，也显示在测试结果和报告的测试结果部分。它和微码版本是排查 CPU 不稳定的线索，单凭这两项不能判定缩缸。
- **硬盘**：每块硬盘的型号下面紧跟自己的健康行（状态、寿命、温度、通电时间、写入量、介质错误），多块硬盘不会混淆。读取量和通电次数在“硬盘健康”详情里。
- **系统编码**：系统给老程序用的文字编码，如 GBK、Shift-JIS。
- **扬声器和麦克风名称**：Windows 的设备名按安装驱动时的语言生成，中文系统也可能是“スピーカー (Realtek Audio)”。工具去掉这类通用前缀，只显示括号里的设备名。
- **电源、机箱、风冷散热器型号**：没有可读取的接口。

## 界面

界面采用 WinForms 原生控件方案，不迁移 WinUI 3/WPF；全部使用系统标准控件，由 Windows 按自身版本绘制，并跟随系统的浅色或深色设置。只有实时曲线、显示器测试图案和自定义背景变换使用图形库绘制，其他列表和表头不自绘。菜单栏是 Win32 原生菜单：“文件”（测试报告、打开报告、打开文件夹、退出）、“工具”（重新读取硬件、重启进入 BIOS、修复为日语 106 键、复制配置、高级信息、诊断工具、网络测速、显示信息、准星、屏幕标尺、性能浮层、测试窗口、硬件信息）、“设置”、“外观”、“语言”和“帮助”。内容区默认用系统窗口色。

右侧监控改为参考 DeepCool 性能页的卡片布局：处理器卡、显卡卡、系统卡、风扇卡；每张卡有原生图标标题和两列指标。处理器/显卡卡显示温度、占用、电压、频率，系统卡显示内存、硬盘、上传、下载，风扇卡显示能读到的风扇/水泵。图标使用 Windows 自带的 Segoe MDL2 Assets 图标字体，不引入图标包；指标文字缩短为“温度/占用/电压/频率/内存/硬盘/上传/下载”。进度条保持原来的系统 ProgressBar 样式；电压按 1.5 V、CPU 频率按 6000 MHz、GPU 频率按 3000 MHz 满量程填充。显卡风扇 0 RPM 显示空轨道，没有风扇传感器时不显示该指标。风扇只显示读得到的：主板接口读数为 0 视为未接并隐藏，显卡风扇为 0 时保留，因为很多显卡低温时会停转。一个都读不到时整张风扇卡隐藏。电压、频率和主板风扇需要管理员权限，部分主板芯片的风扇读数可能一直为 0。风扇进度条按每个传感器本次观测到的最高转速自动调整，不使用固定 3000 RPM，也不把观测值当成硬件额定上限；没有观测上限时不画进度条。不同规格的风扇会各自形成自己的比例，不会被同一个 3000 RPM 统一限制。

上传、下载的进度条以当前活动有线或无线网卡的链路速率为基准，使用对数刻度，避免千兆链路上的普通流量落在零像素；只统计当前选中的一块网卡，不会把有线、无线和其他虚拟网卡相加。数字仍显示实际速率，不把链路速率说成运营商实际带宽；没有读到链路速率时保留空进度条轨道，不隐藏。实时监控标题行右侧的“实时曲线”打开独立窗口，用现有采样数据绘制处理器、显卡、内存、硬盘使用率和上传、下载的动态曲线，不新建第二个采样器；窗口可以保持打开，测试运行中也可查看。曲线使用标准 `PictureBox` 和系统绘图 API，不引入第三方图表组件。悬浮窗在启动时默认显示，可通过“外观 → 悬浮窗”或托盘菜单再次打开；默认是不透明玻璃质感的圆形球，球内液体高度表示内存占用，液体颜色按 CPU 温度在蓝到红之间渐变，温度越高气泡越多；圆外纯透明，球体不透明以避免背后的日期/电压文字透出闪烁。拖到左/右边缘后磁吸停靠为约 13 逻辑像素宽的窄竖条，拖到顶部/底部边缘时改为 150×13 逻辑像素的横条；停靠位置跟随拖到的位置，不固定到左侧。竖条/横条只显示液体高度，拖离或右键取消停靠后恢复圆形球，只显示能读到的 CPU 温度和内存百分比，不显示显卡温度，不显示清理按钮。单击切换信息显示，双击整理内存；右键菜单提供停靠左侧、停靠右侧、取消停靠、清理内存、垃圾清理和隐藏。整理会强制其他程序换出内存，活跃程序可能短暂变慢，因此只允许手动触发并在执行前确认，不把它描述为性能提升。Windows 没有原生圆形悬浮控件，圆形、玻璃质感和文字由标准无边框 Form 加 GDI+ 绘制；使用分层窗口和圆形区域保证圆外纯透明，球体本身不透明以避免背后文字闪烁；不引入第三方 UI 库。

“工具”菜单有重新读取硬件、重启进入 BIOS、修复为日语 106 键、复制配置、高级信息、诊断工具和垃圾清理。高级信息和诊断工具的表格都可点击列头排序、拖动列、调整列宽、右键隐藏列和复制当前行。“设置”菜单打开设置；工具菜单、主窗口右键和托盘右键都可打开垃圾清理。“帮助”菜单有使用说明、检查更新和关于（只打开网页，不自动下载）。顶部不再有单独工具栏；高级信息入口在左侧硬件列表下方，避免新增按钮行。

主界面保持分栏：左侧主栏是实时监控，右侧次栏是硬件配置，测试控制和结果放在监控下方；可通过“外观”菜单显示或隐藏硬件、监控。只显示监控时，监控占满窗口，CPU、显卡、系统卡片保持 2×2 排列，不出现滚动条；风扇卡作为紧凑底部区域。所有指标进度条始终显示轨道，读不到数值时显示空轨道，不会隐藏进度条。还可以让窗口置顶，用系统调色盘改背景颜色，或选一张背景图片。图片默认保持比例缩放，短边贴合窗口，长边居中裁掉。“调整背景图片”可以拖动位置、滚轮或滑块缩放（20%–500%）、旋转和镜像；缩小后露出的部分用镜像平铺补满，接缝自然连续，所以不做边缘模糊。这些选择只保存在本机设置里。按钮等系统控件保持原样，图片较花时文字可能不易看清，可用“恢复默认背景”还原。超大图片载入时缩小到长边 3840 像素，避免占用过多内存。原生菜单栏在深色模式下由系统绘制，可能保持浅色。名称和版本号只显示在系统标题栏。窗口不设硬最小尺寸，可以自由缩小；文字优先换行，内容确实放不下时才滚动。窗口尺寸和位置保存到本机设置文件，下次启动恢复。

实时监控的文字和进度条颜色用系统进度条自带的状态色。Windows 没有公开规定数值范围，这里的范围是本工具自定的：使用率和网速（相对当前网卡速度）80% 变黄、95% 变红；温度 85 °C 变黄，到温度保护阈值变红。

右下角的版权声明可点击，跳转到网站（`/tools?tab=hardware`），该分区首位就是下载卡片。

测试控制区固定为两行按钮：第一行显卡、处理器，第二行内存、硬盘、外设测试。硬盘健康和处理器信息已移入高级信息；扬声器和麦克风测试统一到外设测试窗口。只有一张独立显卡时不显示选择栏，多张时才显示。集成显卡不做压力测试：它和 CPU 共用功耗与散热，CPU 测试已覆盖。没有独立显卡时，双烤和显卡测试禁用并说明原因，CPU 测试仍可运行。

## 高级信息

左侧硬件列表下方的“高级信息”打开独立窗口，按计算机概览、处理器、显卡、主板、内存、硬盘、显示器、网络、外设、散热与电源、Windows、软件与驱动、事件日志、其他分类显示。窗口使用主窗口已经读取的硬件清单和当前传感器快照，不会为打开窗口再次枚举设备或启动第二个传感器来源。默认表格只显示属性、值、状态和来源；分类和组列可在列头右键中显示。CPUID、BIOS 厂商/SMBIOS 版本/固件类型、HDR/色深/色彩编码、逻辑卷等额外信息会和系统信息一起显示，来源列标明数据来自 WMI、DisplayConfig、CPUID 或 DriveInfo。

每个属性带状态和来源：已获取、不支持、权限不足、接口不可用、读取失败、尚未采集。默认使用系统原生列表（ListView）保持原外观；点击列头排序、拖动列顺序、调整列宽；右键列头可把列宽置零隐藏，再右键恢复。没有 OwnerDraw，也不自绘表头。搜索会同时匹配四种语言的字段名、原始值、传感器名和来源；刷新、复制和导出 JSON 可用。刷新只重建当前快照；测试运行期间也可以打开窗口，显示的是最近一次采样。

“完整信息”把语言、格式、系统区域和系统编码合并为“语言环境”，把安装日期和上次开机合并为“系统记录”，不再单独占行。

## 外设测试

“外设测试”打开一个窗口，包含音频、显示器、键盘、鼠标、摄像头、手柄六类。键盘测试显示完整日语 106 键视觉键盘（主键区、导航区、数字小键盘和 JIS 专用键），按下的键点亮、测试过的键保留颜色，并统计同时按下键数和最多同时键数；可在日语 106 键和英语 101 键视觉布局之间切换。鼠标测试统计左/右/中键、后退/前进侧键、四向滚轮、Ctrl+滚轮缩放、可疑连击、回报率估算和可选的移动轨迹。显示器信息行显示当前连接的显卡类型和接口，例如“独立显卡 DisplayPort”或“集成显卡 HDMI”，不重复 GPU 型号；无法取得类型或接口时省略对应项。显示器测试使用与网页版一致的 13 项全屏套件：综合图案、黑/白/红/绿/蓝纯色、25/50/75% 均匀度、色差、渐变、锐度、可视角度、Gamma 和移动响应时间；滚轮或方向键翻页，空格隐藏/显示控件，Esc 退出，操作区 3 秒无操作自动隐藏，左侧进度栏可直接跳转；色差、渐变、锐度、Gamma、响应时间都有各自的亮度、差值、段数、字号、速度、间距和方块颜色设置，并提供恢复默认。显示器、键盘、鼠标和触控板结果需要人工确认，不能自动判定通过；触控板无法与鼠标可靠区分，窗口会明确提示。

## 游戏准星

“工具 → 测试窗口”可把现有测试控制和测试结果一起移到独立窗口，“工具 → 硬件信息”可把硬件面板移到独立窗口；关闭后自动归位，内容复用主窗口控件，窗口按自身宽度显示，不受主窗口列宽限制。窗口置顶在“设置 → 一般”。“外设测试 → 摄像头”列出相机设备，并打开 Windows 相机查看实时预览；本程序不采集或保存画面。“工具 → 性能浮层”可在屏幕顶部显示 CPU/GPU 占用和温度、CPU/GPU 频率和功耗、内存、显存、硬盘、网关延迟、分辨率和刷新率，透明背景、点击穿透。延迟是到默认网关的 ICMP 往返时间，不是游戏服务器延迟；FPS 和帧延迟需要 PresentMon/ETW 或游戏内注入，本工具不注入游戏，因此没有这两项。“工具 → 屏幕标尺”可显示主显示器四边的像素刻度，默认每 50 px 短刻度、每 100 px 长刻度和数字，颜色、不透明度和刻度间距可在设置调整，点击穿透。“工具 → 显示信息”可查看主显示器分辨率、当前刷新率、DPI 和缩放比例。“工具 → 网络测速”通过 Cloudflare 公共端点测量延迟、抖动、下载和上传，并会发送约 12 MB 测试流量。“工具 → 准星”可开关屏幕中央准星，托盘右键也放同一个开关。准星支持点、十字、T、圆环，可改颜色、长度、粗细、间隙和不透明度；形状、颜色、长度、粗细、间隙、不透明度、预览和“启用准星”开关都在“设置 → 准星”标签内，不再打开单独窗口，设置会保存。设置窗口按“一般”“测试”“准星”“游戏”分类；游戏标签可调性能浮层字号、文字颜色和显示项目。

它是透明置顶叠加层：不注入游戏、不读取或修改游戏内存、不发送键鼠输入。无边框窗口模式最稳定，独占全屏可能看不到；部分游戏的反作弊规则可能限制叠加层，使用前请确认游戏规则。

## 诊断工具

“工具 → 诊断工具”打开只读的启动项、已安装软件、进程、事件摘要和系统工具入口；垃圾清理是独立窗口，不在诊断工具里。启动项读取 Run、RunOnce 和启动文件夹；已安装软件读取标准卸载注册表，卸载按钮只启动软件自己的卸载程序；事件摘要统计近 30 天 WHEA、Kernel-Power、BugCheck、TDR、磁盘和 Ntfs 事件数量，只作为排查线索。不会自动删除启动项、修改注册表或上传数据。

垃圾清理窗口只扫描当前用户临时目录、Windows 临时目录、回收站和缩略图缓存。先扫描并显示大小，用户勾选并确认后才删除；正在使用的文件跳过。不做注册表清理、预读取删除、系统还原点删除或 Windows Update 缓存强制清理。

程序只保留一个主窗口：重复启动不会打开第二个窗口，第二次启动会唤回已运行窗口后退出。设置中可以开启“关闭窗口时后台运行”和“开机自启”。开启后台运行后，关闭主窗口会静默转入后台，不弹提示、不发气泡通知、不弹确认框，测试中也会继续运行；有托盘图标时双击恢复，右键可打开、悬浮窗、实时曲线、诊断工具、垃圾清理、设置或退出。托盘图标只控制是否显示图标：不显示图标时程序同样在后台运行，再次启动程序即可唤回主窗口。隐藏到后台不会卸载本次运行的 PawnIO 驱动；真正退出程序时仍按原有安全规则清理本次安装的驱动。

## 安全启动

安全启动只能在 BIOS 里开启，Windows 没有通用接口可以代为开启，这是它的安全设计。安全启动未开启时，“文件 → 重启进入 BIOS”可用：确认后立即重启进入 BIOS，并提示修改位置。需要管理员权限。开启 BitLocker 的电脑可能会要求恢复密钥。

## 内存和硬盘工具

| 工具 | 做法 | 限制 |
| --- | --- | --- |
| 硬盘健康 | NVMe 直接读标准健康日志（0E、寿命、备用空间、通电时间等）；其他硬盘在管理员模式下通过 DiskInfoToolkit 读取 | USB 硬盘盒和 RAID 可能读不到 |
| 内存测试 | 默认用可用内存的 70%，运行 2 分钟，循环自地址、移动反转和随机序列 | 系统占用的内存测不到，不能替代 MemTest86 |
| 硬盘测试 | 写入 1 GiB 临时文件，读回校验后自动删除，并测 4K 随机读 | 单队列速度，低于产品标称值；剩余空间不足时不运行 |
| 外设测试 | 扬声器和麦克风在外设测试窗口中；显示器、键盘、鼠标和手柄也在同一窗口 | 主观项目由员工确认；录音不保存；触控板无法与鼠标可靠区分 |

判定规则：ATA 硬盘的 05、C5、C6 原始值不为 0 或寿命不超过 10% 为“注意”（CrystalDiskInfo 的默认规则）。NVMe 按规范的 critical warning 位判定：备用空间耗尽、可靠性下降、只读模式为“故障风险”，其他警告、介质错误（0E）大于 0 或寿命不超过 10% 为“注意”。

## 标准测试

| 阶段 | 默认时长 | 说明 |
| --- | --- | --- |
| 初始化 | 最长 30 秒 | 等待传感器开始报告 |
| 待机采样 | 60 秒 | CPU 平均使用率超过 30% 时标记“待机条件未达成” |
| 双烤 | 120 秒（取显卡和 CPU 设置时长中较长者，可设 60–300） | 显卡运行 Direct3D 11 计算着色器，全部 CPU 逻辑核心同时运行哈希和浮点矩阵，结果分别校验 |

“显卡测试”“CPU 测试”按钮单独运行一项，时长按各自设置。

传感器每秒采样一次。每个传感器按阶段分别统计最低、最高、算术平均和有效样本数，不混合不同传感器。

### 安全机制

- 随时可停止：按钮立即停止，Esc 先确认。
- 温度保护默认 CPU 100 °C、GPU 核心 95 °C，可在设置中修改。部分桌面 CPU 满载时会按设计保持 95 °C 左右，所以默认值不设得更低。
- 任一设备达到温度保护或传感器中断，两项负载一起停止。
- 温度传感器中断 5 秒即停止负载。
- 负载超过计划时长 15 秒仍未结束时判定超时，并继续后续流程。
- 读不到设备温度时必须人工确认，确认后该项最长 60 秒，结果不判定为通过。
- 这些机制不能替代硬件自身的温度保护。

### 结果判定

| 情况 | 项目状态 | 整体结果 |
| --- | --- | --- |
| 校验错误、设备丢失、驱动重置、异常退出、超时、过热、负载不足 | 发现异常 | 发现需要确认的问题 |
| 读不到温度、无法确认负载 | 数据不足 | 检测未完成 |
| 手动停止、传感器中断、待机条件未达成 | 未完成 | 检测未完成 |
| 没有可测试的 GPU | 不支持 | 检测未完成 |
| 所有请求的项目都通过 | 通过 | 未发现明显异常 |

负载门槛只用于发现未真正运行的负载：CPU 平均 70%、GPU 平均 50%。

测试结果和报告还列出负载下的 CPU 功耗、频率、电压和显卡功耗，读不到的不显示。没有管理员权限时 CPU 传感器读数为 0，工具按未读到处理。

## 散热方式推测

| PUMP 转速 | CPU 风扇转速 | 结果 |
| --- | --- | --- |
| 有 | 有 | 可能是水冷 |
| 无 | 有 | 可能是风冷 |
| 有 | 无 | 接线可能异常，提示检查散热器风扇接口和安装 |
| 无 | 无 | 未取得散热设备信息，并提示无风扇电脑属于正常现象 |

- 转速为 0 或无效都算“无转速”。
- 只统计主板、Super I/O、EC 和 USB 散热控制器上的传感器，不统计显卡风扇。
- `CPU Optional Fan` 和未标注用途的 `Fan #N` 不算 CPU 风扇。
- 结果始终是推测。报告以员工确认为准；未确认时标注“推测”。

## 界面和快捷键

防乱码：语言文件和报告都是 UTF-8，HTML 声明了字符集，所有系统接口都用 Unicode 版本，结果不依赖系统代码页。工具语言和 Windows 区域相互独立：数字、日期固定为公历和西文数字格式，不随区域变化（小数点、佛历、其他数字）。语言对应的字体缺失时由 Windows 字体链接补字。固件字符串里的控制字符和无法解码的字符会被去掉。控制台探针输出 UTF-8，被其他程序用系统代码页读取时可能显示乱码，需要文本时请用 `--json`。

## 报告和数据

- 测试报告：A4 HTML，用默认浏览器打开后打印或另存为 PDF。
- 技术记录：JSON，格式见 [JSON 格式说明](docs/json-format.md)。在网站的服务表单点“导入测试报告”选择它，机种和测试结果会填入表单。验收、签名都在网站表单完成，工具不再包含。

## 已知限制

- 两张同型号显卡：传感器按名称对应显卡，无法区分。温度保护按其中最高的值，负载按其中最忙的值。如果传感器数量少于显卡数量，读数可能不属于所选显卡。
- 显示器只列出当前活动的输出；尺寸来自 EDID，投影仪等可能没有数据。
- 磁盘温度只列在探针的传感器中，未和磁盘列表关联。
- 不读取节流标志，也不判断频率异常下降。
- 内存时序和屏幕材质无法通过通用接口取得，未显示。
- 未做代码签名，Windows 可能显示安全提示。
- 自动安装和退出卸载的结果见验证记录；需要重启的情况只有单元测试。
